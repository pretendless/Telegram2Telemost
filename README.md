# tg2tm

## Что это

Бот [@tg2tmbot](https://t.me/tg2tmbot) принимает запрос на перенос набора стикеров из Telegram в Телемост. Человек присылает название и ссылки на наборы. Очередь хранит Cloudflare Worker. Загрузку выполняет отдельная сессия браузера в GitHub Actions: job открывает сохранённый вход Яндекса и собирает пак в боте «Стикеры».

Workflow поднимает браузер. Воркер принимает сообщения Telegram, хранит очередь и публикует готовый пак.

## Как проходит запрос

1. Человек отправляет `/create`.
2. Следующее сообщение — только название, без ссылок, не длиннее 100 символов. Слишком длинное название бот не принимает и спрашивает снова.
3. Следующее сообщение — одна или несколько ссылок `t.me/addstickers/…`, по одной в строке. Порядок ссылок задаёт порядок стикеров. Worker спрашивает у Telegram число стикеров в каждом наборе. Сумма должна быть больше 0 и не больше 150: это лимит одного пака в Телемосте. Если набор не найден или сумма больше 150, бот пишет, в чём ошибка, и снова ждёт ссылки. Название при этом сохраняется.
4. Принятый запрос записывается в очередь в KV. Повтор того же названия с тем же набором ссылок не принимается. Другое название или другой набор ссылок становится новым запросом. Сообщение без предшествующего `/create` в очередь не ставится.
5. Если workflow Telemost сейчас не выполняется и в очереди есть ожидающий запрос, worker вызывает `workflow_dispatch` для `.github/workflows/telemost-session.yml` (режим `restart`, ветка по умолчанию). Пока этот job разбирает очередь, второй запуск на каждый пак не создаётся.
6. Job восстанавливает сохранённую сессию Яндекса, скачивает стикеры и готовит картинки под ограничения Телемоста, затем поднимает Chromium. В чате бота «Стикеры» скрипт создаёт пак и отправляет картинки по одной: команда нового набора, название, файл, при необходимости эмодзи, ожидание ответа бота, затем следующая картинка. В конце пак закрывается, и worker получает ссылку. Если сохранённой сессии нет, job сообщает об этом и браузер для загрузки не поднимает. Сессию создаёт администратор командой `/login` в том же workflow.
7. Пока браузер открыт, тот же job забирает следующий запрос. Приоритетный запрос идёт раньше обычного и ждёт, пока текущий пак закончится. Пустая очередь ждёт новые запросы 90 секунд и затем завершает сессию. Лимит job — 360 минут. Сессия останавливается за 15 минут до него: незавершённый пак остаётся в очереди, и воркер может поднять следующий запуск.
8. Когда у пака есть ссылка Телемоста, worker закрывает строку очереди и публикует в канале [t.me/tg2tm](https://t.me/tg2tm) один пост: название и ссылка. Человеку, который прислал запрос, бот ведёт одно сообщение: место в очереди, ход «стикер N из M», затем ссылка или ошибка.

Администратор может прислать название и ссылки одним сообщением, минуя шаг `/create`. Он же смотрит очередь, пропускает зависшую загрузку, перезапускает сессию и входит в Яндекс. Эти команды есть только у администратора.

## Из чего состоит

Запрос принимает Cloudflare Worker в `worker/`: вебхук Telegram, очередь и прогресс в KV, вызов GitHub Actions. Картинки и диалог с Телемостом живут в `scripts/`. `fetch_and_convert.py` скачивает набор и готовит файлы. `telemost_upload.mjs` ведёт чат бота «Стикеры» через Chrome DevTools и после каждой картинки ждёт ответ. `queue_drain.mjs` забирает из очереди следующий пак в той же сессии. Workflow `.github/workflows/telemost-session.yml` собирает образ браузера из `vm/` и держит одну сессию: следующий запуск ждёт в очереди GitHub, пока браузер занят. Ограничения пака и выключенный буферный канал записаны в `config/settings.json`. Подготовленный файл — PNG 512×512, не больше 512 КиБ; в одном паке не больше 150 стикеров. Выкладка worker — ручной workflow `.github/workflows/deploy-worker.yml`.

## Что сейчас сделано просто

В бота «Стикеры» уходит одна картинка за раз. Следующая отправляется после ответа на предыдущую. В репозитории есть второй путь: сложить несколько картинок в буферный канал Телемоста и переслать их боту. Этот путь выключен. В `config/settings.json` поле `staging` равно `false`, поэтому загрузка идёт прямо в чат «Стикеры».

## Как запустить

Worker выкладывается workflow **Deploy worker** (`.github/workflows/deploy-worker.yml`). Запуск ручной, после того как изменения worker попали в ветку по умолчанию. Workflow проверяет секреты репозитория `CLOUDFLARE_API_TOKEN` и `CLOUDFLARE_ACCOUNT_ID` и выполняет `npx wrangler deploy` в каталоге `worker/`. Пустое поле environment — выкладка окружения по умолчанию.

Проверка логики worker без Cloudflare и без токенов, Node 22:

```bash
cd worker
node --test
```

Сессию браузера поднимает workflow **Telemost session**. Вызов из бота и кнопка Run workflow работают, когда файл workflow лежит в ветке по умолчанию. Новый запрос при простое запускает загрузку сам. Вход в аккаунт Яндекса — команда администратора `/login`.

## Команды

| Команда | Что делает |
| --- | --- |
| `/start`, `/help` | Как прислать пак |
| `/create` | Новый запрос: сначала название, затем ссылки |
| `/format` | Формат и пример. `/example` отвечает тем же текстом |
| `/status` | Свои запросы в очереди |
| `/stop` | Сбрасывает незаконченный ввод. Очередь и текущую загрузку не трогает |
