# @tg2tmbot — команды и уведомления

Бот **Telegram2Telemost** (@tg2tmbot) принимает запросы на перенос стикеров в Телемост и сообщает о ходе работы.

## Пользователи

| Команда | Описание |
| --- | --- |
| `/start`, `/help` | Как прислать пак; включает подписку на общие уведомления |
| `/create` | Начать новый запрос (после этого — одно сообщение с паком) |
| `/format` | Формат одного сообщения с паком |
| `/example` | Пример набора |
| `/status` | Ваши запросы в очереди |
| `/stop` | Отписаться от общих уведомлений подписчиков |

**Запрос пака:** сначала `/create`, затем одним сообщением: первая строка — название, дальше ссылки `t.me/addstickers/…`, до 150 стикеров. Сообщение без предшествующего `/create` бот не ставит в очередь (администратор может прислать пак сразу, как раньше).

Повтор того же **готового** названия или того же набора ссылок не принимается — измените название или список ссылок.

После принятия запроса бот пишет позицию в очереди и ведёт **одно сообщение** с прогрессом по этому запросу: очередь → начало загрузки → «стикер N из M» → ссылка или ошибка. Подписка (`/start`) по-прежнему даёт отдельные сообщения о процентах для канала подписчиков; карточка запроса не дублирует их.

## Администратор (chat `8502935020`)

| Команда | Описание |
| --- | --- |
| `/queue` | Очередь: кто ждёт (приоритет выше обычных, FIFO внутри группы), что загружается (N из M), недавние готовые/ошибки; «зависшие» uploading с уже завершённым прогрессом в KV закрываются как готовые |
| `/unstick` | При простое Actions: снять зависшую «загружается», закрыть как «готов» если прогресс уже done/error в KV, иначе вернуть в очередь; автозапуск **следующего** queued-пака (приоритет → FIFO). Пока Actions идут — строку «загружается» не снимает, но может закрыть её как «готов» по KV; после run — повторить при необходимости |
| `/skip` | Пометить текущую «загружается» как ошибку и перейти к следующему в очереди (если Actions не идут) |
| `/status` | Кратко: `идёт` / `простаивает` и текущий пак |
| `/restart` | Прервать текущий Actions и один новый запуск с `main`; выбор пака — только **queued/uploading** из KV, не «призраки» из каталога `packs/07…` без активной строки очереди |
| `/login`, `/connect`, `/upload` | Запуск браузера / ручная загрузка (как раньше) |

При **каждом новом** запуске workflow Telemost в админ-чат приходит одно сообщение: **причина** (новый запрос в очереди, следующий пак, `/restart`, `/login`, …) и ссылка на run Actions. Ход загрузки по-прежнему правит одну **карточку** «стикер N из TOTAL».

Один запрос очереди → один пост в канале: публикация идёт через `/progress` в воркере (не дублируется из VM). После `done` и ссылки на пак строка очереди закрывается и при простое Actions стартует **следующий** queued-пак.

Повторная загрузка **старого каталогового** пака (папка `packs/NN-…` без строки в очереди) — только через dispatch с `TG2TM_CATALOG_RETRY=1` в окружении prepare (не через обычный `/restart`).

Обычные пользователи **не** могут `/restart`, `/queue`, `/unstick`, `/skip`, `/login`, `/connect`, `/upload`.
