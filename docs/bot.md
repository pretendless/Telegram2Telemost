# @tg2tmbot — команды и уведомления

Бот **Telegram2Telemost** (@tg2tmbot) принимает запросы на перенос стикеров в Телемост и сообщает о ходе работы. «TG2TM на связи» — только в `/start`. «Соединяю» — только в начале `/create`, «Приняла» — только когда название принято, «Передаю в очередь» — только когда запрос поставлен, «Линия свободна» — только на пустой `/stop`. Числа, ошибки и место в очереди остаются дословными. Карточка хода — строка «стикер N из M», без этой подписи. Пост в канале — только название набора и ссылка.

## Пользователи

| Команда | Описание |
| --- | --- |
| `/start`, `/help` | Как прислать пак; включает подписку на общие уведомления |
| `/create` | Начать набор: название, затем стикеры или ссылки, затем `/done` |
| `/format` | Формат сообщения с паком и пример набора (`/example` — то же) |
| `/status` | Ваши запросы в очереди |
| `/stop` | Прервать ввод и вернуться к командам (не снимает пак из очереди и не останавливает загрузку) |

**Запрос пака:** `/create`, затем сообщение только с названием (без ссылок, не длиннее 100 символов), затем стикеры из наборов и/или ссылки `t.me/addstickers/…` — сколько угодно сообщений, в любом порядке, до `/done`. Стикер с `set_name` добавляет весь свой набор. После каждого добавления бот пишет, сколько добавлено и сколько всего из 150. Тот же набор второй раз не считается. Если добавление превысило бы 150, бот его не берёт и оставляет уже собранное; сообщение с несколькими ссылками принимается целиком или не принимается вовсе. Стикер без набора бот объясняет и ничего не меняет. `/done` ставит запрос в очередь; пустой `/done` просит стикер или ссылки. Слишком длинное название бот не принимает и снова просит название. Повторный `/create` начинает с названия. `/stop` стирает незаконченный ввод, в очередь ничего не ставит. Другая команда (`/status`, `/restart`, …) выполняется как обычно и диалог не стирает. Сообщение без предшествующего `/create` бот не ставит в очередь (администратор может прислать пак сразу, одним сообщением, как раньше).

Повтор готового запроса не принимается, только если совпали **и** название, **и** набор ссылок. Другое название с теми же ссылками или то же название с другими ссылками ставится в очередь. Если совпали оба, бот называет это совпадение и снова спрашивает название, как после `/create`.

После принятия запроса бот пишет позицию в очереди и ведёт **одно сообщение** с прогрессом по этому запросу: очередь → начало загрузки → «стикер N из M» → ссылка или ошибка. Подписка (`/start`) по-прежнему даёт отдельные сообщения о процентах для канала подписчиков; карточка запроса не дублирует их.

## Администраторы (`LOGIN_CHAT_IDS`: `8502935020`, `5513343655`)

| Команда | Описание |
| --- | --- |
| `/queue` | Очередь: кто ждёт (приоритет выше обычных, FIFO внутри группы), что загружается (N из M), недавние готовые/ошибки; «зависшие» uploading с уже завершённым прогрессом в KV закрываются как готовые |
| `/skip` | Пометить текущую «загружается» как ошибку и перейти к следующему в очереди (если Actions не идут) |
| `/status` | Шаг сессии: очередь, запуск Actions (и ссылка на run, если она уже есть) или «стикер N из M». Голое «простаивает» — только когда нет очереди и загрузки |
| `/restart` | Прервать текущий Actions и один новый запуск с `main`; выбор пака — только **queued/uploading** из KV, не «призраки» из каталога `packs/07…` без активной строки очереди |
| `/project` | Вопрос или задача для Cursor Cloud Agent: мгновенный ack в TG, затем фоновый dispatch `cursor-agent.yml`. Actions читает prompt из KV, запускает агента на `pretendless/tg2tm` (`main`) и шлёт краткий итог через `POST /project/reply`. Issue (`project-prompt.yml`) — только если у воркера `PROJECT_ALSO_CREATE_ISSUE=1`, сбой issue не отменяет агента. В GitHub нужны `CURSOR_API_KEY`, `UPLOADER_SECRET` и `TG2TM_PROGRESS_URL` (`https://tg2tmbot.prtndz.workers.dev/progress`). Проверка ключа: Actions → **Check Cursor API**, без curl на своём компьютере; после деплоя воркера то же самое — `/ghrun check-cursor-api.yml` |
| `/ghrun` | Запуск произвольного workflow: `/ghrun <file.yml> [key=value …]`. Только админ; опционально `GH_WORKFLOW_ALLOWLIST` |
| `/login` | Войти в Яндекс. Без метки — аккаунт `default`, с меткой — `/login work`. `/connect` — тот же вход, в меню его нет |

При **каждом новом** запуске workflow Telemost в админ-чат приходит одно сообщение: **причина** (новый запрос в очереди, следующий пак, `/restart`, `/login`, …) и ссылка на run Actions. Ход загрузки по-прежнему правит одну **карточку** «стикер N из TOTAL».

Один запрос очереди → один пост в канале: публикация идёт через `/progress` в воркере (не дублируется из VM). После `done` и ссылки на пак строка очереди закрывается.

**Одна сессия Telemost — вся очередь:** в режимах `upload` / `restart` один job Actions держит браузер открытым и в цикле: `claim` → загрузка → `/done` → terminal `/progress` (release в KV) → снова `claim`, пока очередь не пуста или не истечёт idle-таймаут (по умолчанию 90 с — очередь может пополняться во время run). Пока job идёт, воркер **не** dispatch второй workflow на каждый пак (`sessionDrain` в progress). **Приоритет:** новый priority ждёт, пока текущий пак полностью завершится; preempt нет. Ошибка одного пака → строка `error`, drain продолжает со следующим. Если job оборвался, а в KV остались `queued`, VM шлёт `POST /queue/drain-complete` — autostart как после обычного `done`.

Повторная загрузка **старого каталогового** пака (папка `packs/NN-…` без строки в очереди) — только через dispatch с `TG2TM_CATALOG_RETRY=1` в окружении prepare (не через обычный `/restart`).

Обычные пользователи **не** могут `/restart`, `/queue`, `/skip`, `/login`. `/unstick` и `/upload` никому не доступны: бот отвечает, что команды больше нет.

## Меню команд в Telegram

Список у BotFather обновляет `worker/setup-bot.mjs` (`npm run setup-bot` в каталоге `worker/`).

- **Все чаты** — `USER_COMMANDS`: `/start` («Как пользоваться»), `/create` («Начать новый набор»), `/format`, `/status`, `/stop`. Короткое описание BotFather — «Стикеры из Telegram в Телемост. Набор: /create, затем /done.» Полное описание — шаги `/create` → название → стикеры или ссылки (в любом порядке, до 150) → `/done`, без «TG2TM на связи».
- **Админ-чаты** из `LOGIN_CHAT_IDS` (`worker/wrangler.toml`, плюс переменная окружения при `setup-bot`; скрипт объединяет оба списка) — полный список `ADMIN_COMMANDS`: пользовательские команды плюс `/queue`, `/skip`, `/restart`, `/project`, `/ghrun`, `/login` (scope `chat` в API Telegram). `/connect` в меню нет. Сейчас это `8502935020` и `5513343655`.

`/help` в меню нет — работает как `/start`.
