# Вход в Телемост с телефона

Загрузка стикеров идёт через бота «Стикеры» в уже открытом браузере (`scripts/telemost_upload.mjs`, Chrome DevTools на порту 9222). Cloudflare Worker из PR #2 этого не умеет: в воркере нет браузера. Эта заметка — как с телефона или чужого компьютера, без Cursor, поднять машину с Chromium, войти в Яндекс ID и сохранить сессию отдельно для каждого аккаунта.

Проверено по коду 12 октября 2026. Живой вход в Яндекс отсюда не запускался.

## Рекомендация

Запускать браузер через **GitHub Actions**, а старт — сообщением боту [@tg2tmbot](https://t.me/tg2tmbot): `/login` или `/connect <метка>`. Воркер вызывает `workflow_dispatch`. В чат приходит QR Яндекс ID. Запасной путь — одноразовая ссылка noVNC, если QR на странице не появился.

Почему так, а не всегда включённая VM:

- Репозиторий уже на GitHub, он публичный. Минуты стандартного runner бесплатны и не кончаются. Новый облачный аккаунт не нужен.
- С телефона достаточно одного сообщения боту. Приложение GitHub — запасной пульт, если вебхук ещё не включён.
- Тот же `vm/Dockerfile` без переделки переносится на домашний компьютер или на Oracle Cloud, если Яндекс не примет американский адрес runner.

Ограничение, из‑за которого может понадобиться второй шаг: runner GitHub стоит в Azure в США, и адрес каждый запуск новый. До входа `telemost.yandex.ru` с такого адреса остаётся на «Подключение…» — это уже было, см. `docs/telemost-sticker-bot.md`. После входа страница открылась. Повторится ли это на адресах GitHub, заранее неизвестно: пул общий и им часто злоупотребляют, а Яндекс может сбросить сессию при смене IP.

Если QR не появляется, Телемост после входа снова висит на «Подключение…» или сессия не доживает до следующей загрузки — ту же картинку Docker поднять на **домашнем компьютере** (лучший вариант, если он в России и может оставаться включённым). Бесплатная замена без домашнего компьютера — **Oracle Cloud Always Free**, home region в ЕС, не в США. Образ один и тот же.

## Что делает человек при каждом входе

Когда секреты уже лежат где нужно и workflow есть в ветке по умолчанию (`main`):

1. В Telegram открыть @tg2tmbot и отправить `/login` или `/connect work`. Метка — латиница, цифры и дефис, до 32 символов. `/login` без метки использует `default`. Одна метка — один аккаунт Яндекса.
2. Бот отвечает, что браузер запускается. Первый запуск ещё собирает образ, это несколько минут. Пока идёт загрузка, второй запуск ждёт: одновременно работает только один браузер.
3. В чат приходит фото QR. Открыть приложение Яндекс, в строке поиска нажать сканер и навести на код. Если вход через приложение Яндекс ID (Ключ), выбрать нужный аккаунт и «Войти по QR». Телефон при этом в интернете.
4. Код на стороне Яндекса обновляется. Если пришло новое фото, сканировать его, старое уже не подойдёт.
5. Бот пишет, что вход выполнен и сессия сохранена. Если Телемост всё ещё на «Подключение…», сессия тоже сохраняется, и об этом будет отдельная фраза.
6. Дальше загрузка этим аккаунтом: `/upload work 03 04`. Номера — папки `packs/`. На GitHub картинок в репозитории нет, поэтому `/upload` с runner имеет смысл только когда PNG уже лежат в `packs/`. На домашней машине их кладёт `scripts/fetch_and_convert.py`.

Пароль Яндекса в чат и в VM при QR не вводится. Его вводит приложение на телефоне.

Пока вебхук воркера не включён (на машине переноса ещё крутится long polling, его из‑за этого входа останавливать не нужно), бот команду не увидит. Тогда тот же запуск с телефона через приложение GitHub:

1. Репозиторий `pretendless/Telegram2Telemost` → Actions → **Telemost session** → Run workflow.
2. Ветка — ветка по умолчанию. Mode `login`, account — метка, chat id — числовой id чата, куда слать QR.
3. Дальше шаги 3–5 те же: QR приходит в этот чат.

Кнопка Run workflow есть только если файл `.github/workflows/telemost-session.yml` уже влит в ветку по умолчанию. Сейчас это `main`. Пока файл только в другой ветке, ни кнопка, ни API не запускают workflow.

## Если QR нет: ссылка на экран

Вместе с первым QR бот присылает ссылку вида `https://<случайное имя>.trycloudflare.com/vnc.html?autoconnect=1&resize=scale` и пароль. Это экран того же Chromium через noVNC.

1. Открыть ссылку в браузере телефона.
2. Ввести пароль из того же сообщения.
3. Дойти вход Яндекса на этом экране. Сюда пароль уже вводится в браузер на чужой машине, поэтому QR предпочтительнее. Ссылка нужна, когда Яндекс показал не QR, а форму, капчу или код из приложения.
4. Ссылка умирает вместе с запуском. VNC слушает только localhost внутри контейнера, наружу его выпускает разовый туннель Cloudflare. Постоянный публичный рабочий стол так не делается.

Пароль на запуск генерируется сам (`NOVNC_PASSWORD` можно задать секретом, но не нужно). В лог GitHub он не пишется. В чат уходит только владельцу из `LOGIN_CHAT_IDS`.

Локально без туннеля экран на `http://127.0.0.1:6080/vnc.html`. Порт 9222 наружу не публиковать.

## Регион

С машины, которую Яндекс считал американской, `https://telemost.yandex.ru` стоял на «Подключение…» / «Попытка подключения повторится через N секунд», пока не был выполнен вход Яндекс ID. После входа чат бота «Стикеры» открылся. Значит логин может снять гео-заглушку, но не обещает, что так будет с каждого датацентрового IP.

Практический порядок:

1. Прогнать `/login` на GitHub Actions и дождаться фразы, что Телемост открылся.
2. Если QR-страница паспорта не грузится, капча не проходит или после входа снова «Подключение…» — не крутить повтор в цикле. Поднять тот же образ дома или на Oracle с home region в ЕС.
3. Не выбирать американский home region «потому что так проще создать аккаунт». Для этой задачи он хуже.

`passport.yandex.ru` и `telemost.yandex.ru` — разные проверки. Паспорт может открыться там, где Телемост висит, и наоборот.

## Риск блокировки

Яндекс видит датацентр, автоматизацию и смену адреса. Что снижает риск:

- Вход по QR, а не ввод пароля в браузер на VM. Пароль на чужой машине не остаётся в истории, если его туда не вводили.
- Один браузер за раз, одна метка — один аккаунт. Не входить пачкой и не делить метку между людьми.
- Не повторять неудачный вход циклом. Капча или просьба подтвердить телефон — повод остановиться и сменить площадку, а не секрет, который надо «обойти».
- Chromium здесь не headless: виртуальный экран и обычное окно. Признак автоматизации всё равно есть (`--remote-debugging-port`, флаги контейнера). Это не маскировка под домашний Chrome.
- Сессия следующего запуска на GitHub придёт с другого IP. Яндекс может попросить вход заново. Стабильный домашний или европейский адрес это снимает.
- Шифр сессии в публичном artifact. Ключ короче 32 символов скрипт не примет, словарный пароль вроде `password` тоже. Слабый ключ равен публикации куков.

Блокировка аккаунта возможна. Этот прототип её не обходит и не обещает, что Яндекс разрешает такой вход.

## Как устроен прототип

```
Telegram  /login work
   →  Worker (PR #2)  POST workflow_dispatch
   →  GitHub Actions  docker build vm/Dockerfile
   →  Xvfb + Chromium + x11vnc + noVNC
   →  passport.yandex.ru QR  →  sendPhoto в чат
   →  куки Яндекса  →  AES-256-GCM  →  artifact telemost-session-work
```

| Файл | Зачем |
| --- | --- |
| `vm/Dockerfile` | Node 22, Chromium, Xvfb, x11vnc, noVNC, скрипты загрузки. Сборка из корня: `docker build -f vm/Dockerfile -t tg2tm-browser .` |
| `vm/start.sh` | Поднимает экран, браузер на `127.0.0.1:9222`, noVNC на 6080. При `ENABLE_TUNNEL=1` качает cloudflared `2026.10.0` и сверяет SHA-256. |
| `vm/login.mjs` | QR, ссылка, сохранение и восстановление сессии. Команды: `login`, `restore`, `save`, `notify`. |
| `vm/worker_login.js` | Разбор `/login`, `/connect`, `/upload` и вызов GitHub API. Это место врезки в воркер. |
| `.github/workflows/telemost-session.yml` | `workflow_dispatch`: mode, account, chat_id, packs. |
| `vm/test/login_vm.test.js` | Без браузера, без токенов, без Яндекса: `node --test vm/test/login_vm.test.js` |

Образ собирается (`docker build -f vm/Dockerfile -t tg2tm-browser .`). В нём Chromium открывает порт отладки, а noVNC отдаёт `vnc.html`. Страница паспорта Яндекса при этой проверке не открывалась.

В образ не копируются `packs/` и `logs/transfer-log.md`. Workflow монтирует эти каталоги из checkout, если они там есть. Каталог стикеров в ветку по умолчанию этим входом не кладётся. `/login` их не читает.

Браузер стартует с `--remote-debugging-address=127.0.0.1` и `--remote-allow-origins=*`. Порт отладки наружу не пробрасывается. В контейнере нужен `--no-sandbox`: так Chromium живёт в Docker. Контейнер не запускать с `--privileged`.

Режим `upload` после восстановления сессии вызывает `scripts/telemost_upload.mjs` с номерами паков. Без номера пака режим не стартует, чтобы случайно не отправить все паки. PNG в git нет и в образ не попадают. На runner загрузка дойдёт до скрипта и остановится, если файлов картинок нет.

Перед `/newpack` или следующим паком в очереди скрипт закрывает открытый диалог бота «Стикеры» одним **`/done`** (с повтором при сбое), а не `/start` — `/start` только показывает меню команд. Если бот ждёт эмодзи, автоматизация не шлёт `/done` вслепую и останавливается с ошибкой.

Дома, когда картинки уже собраны:

```bash
docker build -f vm/Dockerfile -t tg2tm-browser .
mkdir -p sessions
# TELEMOST_SESSION_KEY и TG2TMBOT_TOKEN задать в окружении, не писать их в файл репозитория.
export MODE=login ACCOUNT=work TELEGRAM_CHAT_ID=<chat id>
docker run --rm --shm-size=1g \
  -p 127.0.0.1:6080:6080 \
  -e MODE -e ACCOUNT -e TELEGRAM_CHAT_ID -e TELEMOST_SESSION_KEY -e TG2TMBOT_TOKEN \
  -v "$PWD/sessions:/var/lib/tg2tm/sessions" \
  -v "$PWD/packs:/opt/tg2tm/packs" \
  -v "$PWD/logs:/opt/tg2tm/logs" \
  tg2tm-browser
```

Загрузка: `MODE=upload` и `PACKS="03 04"`. Ключ тот же, иначе файл сессии не откроется.

Oracle: home region в ЕС, shape Ampere в пределах 2 OCPU и 12 ГБ, Docker, та же команда. Порт 9222 в security list не открывать. noVNC либо только с SSH-туннеля, либо через именной туннель Cloudflare, не через открытый 6080 в интернет без пароля. Секрет `TELEMOST_SESSION_KEY` положить в файл с правами `600` вне git.

## Сессия

Файл `<метка>.tg2tm-session`:

- заголовок `TG2TM1`;
- соль scrypt (N=16384, r=8, p=1) и ключ AES-256-GCM из `TELEMOST_SESSION_KEY`;
- куки только доменов `yandex.ru`, `yandex.com`, `yandex.net`, `ya.ru`;
- localStorage этих же origin, с обрезанием длинных значений.

Вход считается состоявшимся, когда есть и `Session_id` (не короче 16 символов), и `sessionid2`. В лог пишутся имена кук, не значения. Файл в git не попадает (`*.tg2tm-session`, каталог `sessions/`).

На GitHub следующий `upload` забирает самый новый artifact с этим именем. Чужой токен на редирект скачивания не уходит. Нет файла — в чат уходит «Нет сохранённой сессии…», браузер не собирается.

Повторный `/login` с той же меткой заменяет сессию. Другая метка — другой файл.

## Секреты

В git, в образ и в текст коммита их не класть. QR и ссылка noVNC — тоже секреты на время запуска: они входят в аккаунт.

| Имя | Куда положить | Кто создаёт | Зачем |
| --- | --- | --- | --- |
| `TELEMOST_SESSION_KEY` | Секрет GitHub Actions | Человек, один раз: `openssl rand -base64 32` | Парольная фраза шифра сессии. Не короче 32 символов. На воркер не копировать: воркер куки не видит. |
| `TG2TMBOT_TOKEN` | Секрет GitHub Actions. То же значение, что секрет воркера `TG2TMBOT_TOKEN` и локальный `config/tg2tmbot.token` | Уже есть у бота | Job шлёт QR и ссылку в Telegram. |
| `GH_DISPATCH_TOKEN` | Секрет воркера | Fine-grained personal access token, только репозиторий `pretendless/Telegram2Telemost`, право Actions: Read and write | `POST /repos/.../actions/workflows/telemost-session.yml/dispatches`. Других прав токену не давать. |
| `LOGIN_CHAT_IDS` | Секрет воркера | Список числовых chat id через запятую | Кто может слать `/login`, `/connect`, `/upload`. Пустой список выключен: команда никому не отвечает запуском. Id есть в `config/tg2tmbot-subscribers.json` после `/start`. |
| `TELEMOST_VM_REF` | Секрет или variable воркера | Имя ветки, которую checkout'ит job | В коде запасной вариант — `main`. Поставить то же имя, что у ветки по умолчанию, если это не `main`. |
| `GH_REPO` | Variable воркера, можно не задавать | — | По умолчанию `pretendless/Telegram2Telemost`. |
| `TELEMOST_WORKFLOW` | Variable воркера, можно не задавать | — | По умолчанию `telemost-session.yml`. |
| `GITHUB_TOKEN` | Выдаёт сам GitHub внутри job | Не создавать | Чтение и запись artifact. В контейнер не передаётся. |
| `NOVNC_PASSWORD` | Не обязателен | Если не задан, скрипт генерирует его на один запуск | Пароль экрана. В репозиторий не писать. |
| `WEBHOOK_SECRET` | Уже секрет воркера | Уже для PR #2 | К браузеру не относится. |
| `UPLOADER_SECRET` | Уже секрет воркера | Уже для `POST /progress` | К входу не относится. |
| `CLOUDFLARE_API_TOKEN`, `CLOUDFLARE_ACCOUNT_ID` | Окружение при `wrangler deploy` | Уже для выкладки воркера | В этот workflow не входят. |

`config/bot.token` (бот, которым скачивают стикеры) этому входу не нужен.

Проверка без секретов: `node --test vm/test/login_vm.test.js`.

## Что завести

Новый аккаунт Яндекса заводить не требуется. Каждая метка — уже существующий аккаунт, которым человек сканирует QR.

Обязательно для пути через бота:

1. Секрет `TELEMOST_SESSION_KEY` в GitHub → Settings → Secrets and variables → Actions.
2. Секрет `TG2TMBOT_TOKEN` там же.
3. Fine-grained PAT → секрет воркера `GH_DISPATCH_TOKEN`.
4. Секрет воркера `LOGIN_CHAT_IDS`.
5. Влить workflow в ветку по умолчанию `main`. Иначе API отвечает 404, а кнопки Run workflow нет.

Отдельно ничего не заводить, если хватает кнопки в приложении GitHub: только пункты 1, 2 и 5. Токен GitHub для диспатча тогда не нужен.

Oracle, Fly, Google Cloud и Render для этого пути не регистрировать. Они нужны только если runner не подойдёт Яндексу. Карту имеет смысл привязывать уже после неудачного `/login` на GitHub.

## Врезка в воркер

Код пульта лежит здесь, чтобы не тащить в этот PR весь воркер из ветки `cursor/cf-worker-bot-a79c`. После того как PR #2 влит, в `worker/src/index.js`:

```javascript
import { handleVmCommand } from "../../vm/worker_login.js";
```

В `answer()`, вместо голого `else if (cmd) return;`:

```javascript
} else if (cmd === "/login" || cmd === "/connect" || cmd === "/upload") {
  await handleVmCommand(env, message, { send });
  return;
} else if (cmd) {
  return;
}
```

В список команд админ-меню (`ADMIN_ONLY_COMMANDS` / `ADMIN_COMMANDS` в `worker/src/logic.js`, их ставит `worker/setup-bot.mjs` для чатов из `LOGIN_CHAT_IDS`) добавить:

| command | description |
| --- | --- |
| `login` | Войти в Яндекс |
| `connect` | Войти в аккаунт с меткой |
| `upload` | Загрузить паки этой сессией |

Пока на машине переноса работает `python scripts/tg2tmbot.py`, вебхук не ставить: Telegram отдаёт обновления только одному получателю. Вход через бота включится вместе с вебхуком, не раньше. До этого — кнопка в GitHub.

Чужой чат на команду получает «Эта команда только для владельца.» и job не создаёт.

## Чего прототип не делает

- Не логинится в Яндекс сам и не трогает аккаунт Телемоста.
- Не останавливает текущую машину переноса и не открывает её Chrome.
- Не скачивает стикеры и не кладёт PNG в git.
- Не хранит куки в репозитории, в KV воркера и в логе.
- Не обещает, что американский runner пройдёт проверку Яндекса. Образ для переноса на другую машину из‑за этого и собран отдельно от workflow.
